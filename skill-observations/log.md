## 2026-09-16

### Observation 1: Review-folder synthesis is a recurring board-lock job

**Status:** ACTIONED (2026-09-16)
**Date:** 2026-09-16
**Session context:** User asked for a complete debate of REVIEWS/opinions.md and REVIEWS/improvements.md as the last upgrade of the year for the new channel.
**Skill:** New skill candidate: review-synthesis (internal)
**Type:** internal
**Phase/Area:** newsroom strategy / v1.0 lock

**Issue:** Two large review dumps (~5,000 lines) mix high-signal consensus (fetch hallucination, YouTube AI policy, grievance officer, lock the repo) with contradictory wishlists (more agents vs fewer, Playwright rewrite vs keep Pillow, auto-publish vs never auto-publish). Treating every suggestion as equal would expand the system instead of locking it.

**Suggested improvement:** If this happens again, a skill should (1) inventory all review files, (2) extract consensus vs conflict, (3) verify each claim against live code, (4) output a ranked DO / DO NOT / LATER board plan, never a rebuild.

**Principle:** When a product is about to freeze, synthesise external reviews into a kill-list and a lock-list. Consensus on safety ships; novelty that fights the existing contract does not.
